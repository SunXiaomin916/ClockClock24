# 构建与验证

以下工具只用于修改源码和重新打包，用户运行发布包不需要它们。

- Node.js 22.12+；执行 `npm ci` 安装锁定开发依赖。
- Python 3：标准库用于制作、验证 ZIP；用 `CC24_PYTHON` 指定可执行文件。
- Windows 包：在 Windows 上用系统 .NET Framework C# 编译器生成辅助程序，无需 Visual Studio。
- macOS 交叉包：Windows 需有创建符号链接的权限；正式 Developer ID 签名／公证需要 Mac 与证书。
- 图标已包含，仅重新生成时需要 Pillow：`python tools/create-icons.py`。

```powershell
npm ci
$env:CC24_PYTHON = 'C:\path\to\python.exe'
npm test
npm run build
```

可以分别运行 `build:windows`、`build:macos`、`build:wallpaper`。`npm run desktop` 启动开发版；Windows 先构建一次准备 `build/native/window-layer.exe`。开发版不登记开机启动。

打包从白名单复制运行资源，排除测试、开发服务器和依赖，桌面内容放入 app.asar。ZIP 保留 macOS 符号链接、Mach-O 与安装脚本的执行权限，写出后逐文件验证 CRC 和 SHA-256。macOS 包修正跨系统构建的资源完整性路径，没有伪装成 Apple 签名包。

构建完成后执行 `npm run verify:release` 核对桌面包内资源与当前源码、Mac CPU 架构及 asar 完整性；执行 `python tools/verify-archives.py` 核对所有 ZIP 的校验和、权限和符号链接。

UI 回归需要 Playwright（开发用，不进入发布包）：

```powershell
# 有现成 Playwright 时，通过 NODE_PATH 指定其 node_modules
$env:CC24_URL = 'http://127.0.0.1:8766'
npm run test:browser
npm run test:desktop
```

桌面测试启动 build/packages 下的 EXE，使用临时用户配置，实际开启／关闭本应用用户启动项，结束时清理测试启动项并退出。已有启用的同版本启动项时不要运行此测试。`CC24_EXE` 可指定另外的待测 EXE。截图与结果默认放系统临时目录，桌面为 `cc24-desktop-qa`，浏览器路径可用 `CC24_QA_DIR` 指定。

历史性能采样见《开发与历史验证》，不能当作 3.0 桌面运行时的新测量结果。

平台依据：[Electron 窗口类型](https://www.electronjs.org/docs/latest/api/structures/base-window-options)、[启动项 API](https://www.electronjs.org/docs/latest/api/app#appsetloginitemsettingssettings-macos-windows)、[Apple LaunchAgent](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html)、[Electron 44 系统要求](https://www.electronjs.org/blog/electron-44-0)。

Windows WorkerW 挂载不是微软保证稳定的公开壁纸 API。辅助程序只调整本应用窗口的父级、位置和样式，不注入 Explorer；失败时返回错误并保留时钟窗口。
